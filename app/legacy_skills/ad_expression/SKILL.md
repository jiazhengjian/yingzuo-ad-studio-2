# 映作广告内容表达

版本：1.3.0。用途：已完成商品理解与创意选择后，写作和审阅中文商品广告内容。本文为项目编写的模型运行时规则，不是 Codex 技能安装包，不执行联网检索或第三方工具。

## 输入边界

从已确认的 ProductBrief 和选中方向开始。事实、未知项、创意假设分别使用：事实可以支撑商品主张，假设用于组织情境，未知项不能写成卖点。原图只能支撑清楚可见的外观信息。商家指定的办公室、门店或其他场所必须贯穿内容，不由美术偏好替换。

不用等待案例库才开始策划。可以根据已知商品和消费情境提出创意，但不能称为爆款规律、消费者调研或已验证转化方案。方法文档和正反例不提供当前商品的事实，也不是换个商品名即可套用的话术。

## 方法一：把商品特点变成观众在意的信息

默认商品表达和商品演示并重。沿着“已知特点 → 对这个受众的关注理由 → 实际话语和画面”组织内容；这是一条检验关系，不要求逐句朗读三段式。

1. 找到可使用的商品依据。功能、配料和价格需要相应商家信息；颜色、轮廓、可见层次可以来自图片。
2. 说明该特点与选中受众、场景有什么关系。例如商家确认的折叠结构可以支持随身备袋子的需要；只有外观资料时可以用具体配色、造型与布置偏好建立审美关系，不能补上快速、省电、轻巧等效果。
3. 在实际 narration 和 visual_role 里兑现这种关系。观众应能看懂或听懂商品为什么值得关注。core_message、audience_takeaway、product_role、purpose 和 message 是作者的概括，不会自动成为观众获得的信息。

功能利益、外观吸引力、日常仪式和分享都可以成为切入点，但要由这件商品的具体依据支撑。没有独家优势不用编比较优势；外观广告也不必伪装成功能广告。不能把“每天都会用”“放在手边”“收进柜子麻烦”等普通习惯直接当成这件商品的独特看点。只说明任何物品都可能常用或值得摆出来，还没有解释为什么关注这个商品。

商品事实可以主要在画面里展示，但不能让台词只剩适用于所有商品的生活感慨，再靠 purpose 声称已经建立购买理由。反过来，也不能把所有事实逐条念一遍代替广告表达。检查完整内容中“特点与关注理由”的连接是否实际成立。

## 方法二：按信息任务写完整广告，再划镜头

内容节拍描述信息怎样发生变化。可以按“引出关注 → 商品提供具体内容 → 完成期待”组织，也可以从商品细节开始，再揭示使用情境。结构由创意选择，不是每条广告必须套用相同三段。

每个节拍回答三个问题：观众此时获得什么；商品怎样参与；画面和台词分别做什么。可用的信息任务包括提出与商品有关的需求、说明已知特点带来的选择理由、演示依据、完成使用情境。按这些任务决定节拍和话语数量，不按事实条数、镜头数或固定句数填格子。没有“20秒只准一两句或两三拍”的偏好，也不把字数少当作高级。

后文承接开头的期待，不能用吸睛开场骗来观看后转向另一主题。结尾可以完成动作、停在商品或结束一句有效邀请，不强制购买指令、标语或尾字。不要用“进入桌面 → 在桌上看细节 → 回到桌面”冒充三次信息推进。

把商品换成不相关品类后，完整内容若原样成立，应检查商品关系。但替换检查只是辅助：清点品类独有的部件也会让其他品类无法替换，仍可能没有建立关注理由。不要求每句话都重复商品名。

各拍保持动作造成的商品状态。切开、取走一部分、拆开包装之后，后文不能无说明回到完好未动的状态。把物品放回原处只是空间变化，不能自动算完成了分享、使用或选择的叙事任务。

再按 `references/director_methods.md` 核对可视商品记忆与逐镜信息增量。前者说明观众如何从交付画面辨认这件商品及其关注理由，后者说明相邻画面各自新增了什么理解。这个方法用于改进 `audience_takeaway`、各拍的 `message` 和 `visual_role`，不新增用户表单，也不要求先写死镜头数。重复特写可以合并，需要看清细节的停留可以保留，不能把镜头多当成信息多。

## 方法三：让画面与声音一起表达商品

画面呈现可见细节、情境、动作和操作；声音可以交代画面看不出的已知商品信息、说明特点与关注理由的关系、解释必要操作或发出有商品关联的邀请。二者共同完成广告，不要求各占一半时长，也不要求每次切镜都有新台词。

商品演示允许说明正在执行的关键步骤，前提是帮助观众理解用途。连续说“镜头向下”“淋面在滴”“一层一层”而没有增加商品意义，需要改写。已知而重要的特点应该表达清楚，不为追求安静删掉必要的产品信息。

每句台词都应承担实际任务。“商品还在这里”“颜色在这里”“它回到原位”通常没有新增信息，可以删除。静音画面仍要完成具体展示或情境任务；不能删光台词让表达检查表面通过，当前有声广告至少保留一句有作用的完整话语。

音画语义相配是最低要求。同义复述可能没有分工；一句泛用生活感慨搭配商品展示，也可能没有建立任何商品理由。只有外观信息时，选取与审美偏好有关的具体看点，让实际画面和台词共同建立外观选择的吸引力，不硬编性能，也不默认只有一两句空泛邀请可写。

画面里的 AI 演示不能冒充实际测评、销量、顾客反应或食用体验。没出现的人物和动作也不能在台词里被说成刚刚发生。

## 方法四：先保留完整表达，再检查工程预算

采用受众能理解的日常语言，有明确对象与完整意思。邀请、设问、简短陈述和克制的幽默均可；不编造“我用了三年”“吃一口就知道”等个人经验，也不为显得口语堆语气词。

避免通用品质口号、抽象大词、空泛赞美和句句感叹号。保留句子的自然长度，不机械压缩成几个四字短语。加句号不代表语义完整；检查主谓搭配、指代和前后因果。抽象的“样子”不能像实体那样“放在桌上”，空间小也不能直接成为选择无关功能的理由。

一个 beat 的完整话语可以跨同一生成段内、属于这个 beat 的一组连续镜头，不必在每次切镜时结束。镜头服务信息任务，不能先锁死短镜头再把自然句截断。不可在不同 beat 或生成段之间接半句话；不能以逗号、顿号、冒号或分号收尾，把剩下半句交给下一个 beat。

当前每个完整 beat 的话语最多29字符。总量与各生成段暂按每秒2.9字符向下取整，标点和空白计数；20秒最多58字符。单段预算以服务端实际分组为准，不因为镜头切换就创建新的生成任务。这只是待真实音频验证的工程硬上限，不是语速标准、推荐密度或音长保证。没有目标字数，不偏好“越少越好”，也不为填满上限补话。先写足必要的商品信息，再在硬预算内完整改写和取舍。

整句话要依次放入各视频生成段的预算。总字数达标不保证逐段可容纳。每个 beat 至少占一个镜头位置，静音也计算在内；每段位置上限以segment_beat_limits为准，不是建议数量。同一个 beat 可以使用多个连续镜头，仍须保留足够的实际展示时间；文字预算与位置均通过，不代表配音或成片时长已验证。

短尾段容不下完整话语时可以静音收束。创意方向里的“回到原场景”“完整外观落定”通常是视觉安排，不要求朗读“还是在这里”。结尾说话须有新意义，不为闭环重复开场的位置。

## 审阅与失败处理

按商品关联、受众关联、事实支撑、音画分工、自然表达、叙事推进六项审阅最终脚本。先审广告核心是否成立，再审句子和节奏。每项只记录一句指向实际台词或画面的可核对结论，不输出隐藏思考过程。

审稿必须看实际 narration 与 visual_role。purpose 写着“建立购买理由”、商品出现在画面里、事实没有错误、句子很短，都不足以证明广告有效。若商品特点和关注理由的关系只存在于作者自述中，必须改写内容。稀疏口号、泛用生活习惯、连续清点外观、重复位置和生硬表达都需要处理；修稿既可以删除无意义话语，也可以补回被遗漏的必要商品信息。

商品关联同时核对可视商品记忆是否由具体画面和台词兑现；叙事推进同时核对逐镜信息增量。不要只因方向里写了“记住产品”或拍了完整商品就标通过。逐镜核对最终由分镜与计划审核继续执行，这里的脚本审核只判断内容是否提供了足够且不重复的视觉任务，不能宣称尚未生成的画面已经通过。

在既有事实和选中方向内先完成修改，再检查新稿。广告核心仍不成立或任何具体问题仍未解决时，对应检查 passed=false、ready=false，说明残留缺口。不要为返回成功机械标通过，也不要因只有原图就一律拒绝外观广告。预算合格不证明有关注理由，模型审稿通过也不代表投放或成片效果成立。


## 生成连续性

分镜是观看时的切镜，生成段是一次模型请求。新的 continuity_v1 策略在30秒内一次生成全部分镜；更长广告先按内容和动作边界分组，每请求2至30秒，不制造1秒尾段。历史 legacy_10s 任务保留原执行协议。

对每个内容节拍标注 boundary_before。continuous 表示上一动作仍在发生或必须直接承接，不能切成独立请求；complete 表示上一整句和动作已结束；scene_change 表示真实场景转换或独立叙事，可优先作为边界。连续动作可用相同非空 continuity_group 绑定，不可为凑时长虚构可切边界。长广告没有安全边界时应重组内容，不能切断半句或动作。

统一声线描述只是生成要求，不是音色锁定能力。独立请求间的原生旁白、音乐和环境声可能不同，不能把分组完成写成声音已经连续或成片已经验收。
