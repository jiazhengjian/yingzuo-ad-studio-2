# 脚本审核

收到初稿字段校验提示时，在本次既定审稿中修正相关字段，并完整检查修订稿的事实、表达、动作容量与状态接续；不额外发起生成或审核调用，不补未知事实，也不只修格式就判通过。

1. 看实际台词与画面能否表达商品在选中故事中的作用，并兑现概要和观看期待。人物互动不能退成静物特写；只在 `core_message` 或 `purpose` 写好主张、引用事实 ID、字段齐全均不充分。商品的生活用途或选择关系可以成立，无需每条证明独家优势。
2. 区分商品事实与情境创作。允许符合已知用途的人物互动和使用演绎；未知口味、功效、价格、材质、促销或真实亲历不能混入。原图一致、指定餐具、商品不变形属于制作要求，不能成为广告卖点或台词主题。
3. 检查期待与兑现、声画分工、完整自然的表达和商品记忆。人物对白逐句核对选定的唯一说话人，画面/动作计划不可让另一个角色开口或让说话人一边吞咽一边说话。拦住泛用感慨、重复信息与连续播报动作；人物邀请和回应可以推进关系，不必逐字念卖点。允许有目的的静默、辨认和停留，不强制每镜新增信息。
4. 逐段独立核对 `timing` 与实际画面。`visual_seconds` 应容纳动作先后、对象辨认和必要停留；`action_plan` 应指出可并行部分。`speech_overlap=true` 才以视觉/说话估计的较大值预算；`false` 必须先视觉动作、后完整台词，两者相加。吃入口、吞咽再回应不能按同时完成；静音动作也不能漏计。字符预算仅估计说话容量，不等于全片可执行。`visual_seconds` 不重复计入程序另算的说话时长；串行段须将二者相加，不能只加各段 visual_seconds 就宣称总量通过。
5. 沿 `start_state`、`end_state` 核对关键人物、道具与消耗状态。`time_transition=continuous` 应自然接续；`ellipsis` 必须说明省略的过程和时间推进，后续分镜须有真实切点。可以省略重复取食而保留故事落点，不能在持续动作中突然空盘或复原。时间省略应位于当前段开始与前段结束之间；省略后的起始状态必须明确，本段自身仍连续可执行。事实未知的份量仍未知。

程序提供的逐拍和总容量是本稿的数字依据。总量超出目标时，至少通过删减、合并或明确省略实际内容消除超额，重新计算修订稿；不得只下调动作估计或把超额总数宣称为通过。

本阶段返回完整修订稿，并以修订后的实际内容填写 `execution_check`：`action_capacity` 明确判断全片联合预算是否足够，`state_continuity` 明确判断状态与时间省略是否成立，`note` 简述依据或剩余问题。两项未通过时不能把整体标通过；不能只填“可执行”而不修正文稿。

收到程序容量反馈或声画审核返修反馈时，先判断过载发生在哪些动作与段落，再在本次审核回复内改稿；有实际分镜时一并核对。保留选中故事核心、商品事实、用户在 `merchant_request`/`conversation` 中明确固定的台词和内容；内部审稿通过不意味着每句已获用户锁定。可删重复动作、压缩非固定台词、重排次要内容，或用明确影视时间省略保留落点；不得偷偷延长片长、改事实或假定快放。重新核对所有审核项后交分镜重排，由最终声画审核再独立检查。无法保留用户固定内容并容纳时返回具体冲突，不继续自发重试。
