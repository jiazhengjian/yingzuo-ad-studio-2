# 商品依据与创意边界

供 `strategy` 与 `direction_review` 共用。商品事实、用户要求、作者创意设定各有来源；有效事实 ID 只证明引用存在，不证明任意主张成立。

## 事实从哪里来

- 商家事实来自原始商家资料。按原文层级理解明确回答的功能，不把它降成“消费者可能关注”，也不扩成未说明的性能结果。缺数值不等于不能介绍功能；例如温度控制可介绍，不能升级为自动恒温或不伤发。
- 图片事实只记录可靠可见的形态、数量、颜色、结构与包装状态。材质观感不等于成分，银色反光不证明金属；无尺度参照不推尺寸。模糊部件可以不写，环、孔、网状或按钮外观不证明其名称、功能或流向。
- 已知用途可正常演示。吹风机可用产品外部的风与发丝关系表达吹风；出风部位未知时，不能从可见环或孔推定出口、让概念流线从该部位喷出，或据外形推定均匀散风、护发机理。此例说明功能与部位证据的区别，不是所有方向的创意模板。
- 规则、历史 AI 文案、候选选择与参考广告不构成本商品证据。原始提问、回答及最新明确纠正共同决定商家意思；已撤回的主张不继续采用。

## 如何用于创意

先按本轮原话与上下文区分广告要求和可选资料，不把所有商品资料都当成必讲清单：

- 用户要求这条广告体现的内容，是每个完整候选共同要回应的任务；并列提出的要求不能由三个候选各认领一部分。即使没有逐字说“每条都要”，在广告目标问题中回答“希望体现外观，也要讲护发”，也不能擅自删去其一。用户明确授权任选、只主打一项或用不同版本测试不同卖点时，才按该取舍组织候选。
- 商品介绍中列出的属性、可供参考的卖点，以及用户允许取舍的内容，可以选择适合本方向的部分；不能因此把所有功能塞满短片。用户最新的撤回、优先级和取舍要求覆盖先前安排，不重复澄清已有明确回答。
- 区分表达对象、视觉风格与功能信息。外观可以由产品画面体现，高级感可以由视觉风格承担，已知功能可以由演示或短旁白传达；不要求所有内容都用台词念出，也不把风格当成产品功效。一个方向可以有一个主要记忆点，同时保留必要支撑信息；主次不等于排他。

三个候选是供用户选其中一条的完整方案，不是一套必须合看才能补齐要求的系列片，除非用户明确要系列。差异主要来自创意机制、开场钩子和品牌世界路径，不靠删掉不同必需诉求制造差异。在核心创意、0–3秒、中段和结尾里让必要要求被看见；仅在标题或备注里提到不算呈现。展开怎样讲清卖点交给选中后的脚本。推荐项同样须完整回应要求，不能只因某个外观方向容易实现就推荐遗漏功能的方案。

商品功能、材质、成分、对比和效果仍须由引用事实支撑。情绪、场景、夸张和幽默写在创意里，不需要另找事实编号，也不能写成功效、测评或证言。完整覆盖不能成为编造技术机理、效果程度或实验结果的理由。先用主次、视觉与声音分工在现有时长内实现；确有信息或固定要求冲突时才说明具体缺口并按现有路径澄清，不默默删除要求或在方向卡中自行宣布放弃。可选卖点无需全讲，必需内容无法可靠表达时不能靠其他候选替它补齐。

受众为何可能在意属于创作判断，推断记入 `brief.assumptions`，不冒充调研或实测结果。人物、地点、相遇与使用情境可以拟议；画面隐喻、演员反应、时间压缩和前后对照不能补证未知效果，也不能冒充真实买家证言。食物广告中吃一口、微笑、再取一口可以是情节，不自动成为口味或功效证明。用户明确禁用人物、食用或体验演绎时遵守。

## 商品约束与创作安排

`production.product_constraints` 只承载来源支持的身份、形态关系和物理边界，引用相应事实；不把谁操作、固定顺序、旧台词等作者建议借事实 ID 升格成商品事实。用户确实固定的动作单独保留，其余安排可以协调。

保持身份不等于状态不变：切块不能变整只，已消耗部分不能复原，附属物随主体移动，分离需要动作。原图没有证明份量，不能把两人分享写成已确认双人份；两口后空盘等过程须有实际动作或明确时间省略。已有切面无需虚构吃一口才能露出层次。商品约束不能同时要求取食又永远完整。

事实不足时不补造；审核发现图片观察错误时，按方向审核的窄范围纠正合同处理。事实判断不等于实际生成媒体已还原正确。
