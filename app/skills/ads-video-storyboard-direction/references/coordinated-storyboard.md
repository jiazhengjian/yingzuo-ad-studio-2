# 内容与分镜协调

## 输入与前置条件

读取选中方向、商品事实/原图、确认情境、声音与角色约定、用户固定内容和运行时能力。有 `draft_script` 时读取其内容与 `timing`，协调内部初稿；没有时直接沿选中方向同次写完整 `ad_script`、实际台词或静默、视觉约定与镜头，不补造一个已确认初稿。选方向不等于逐句确认，未固定台词和时间仍可协调。已有图片则读取实际可见内容，计划文字不代表图片已符合要求。

接收已选方向的结构、一句核心画面、开头和收尾。旧方向若还有产品记忆、声音任务或创意展开，一并沿用；没有则从这句画面、开头、收尾和已审脚本来排，不要补写回方向。依 `brief.creative_intent` 区分用途环境与用户明确片场要求。产品展示不因用户职业或“故事核心”改成人物剧情。普通修改沿用所选概念，用户明确更改时同步受影响内容。

保留已选短句和旧字段里已经写明的必要信息；可调整篇幅与声画分工，不只剩主重点，也不从未选候选补造要求。

## 执行

沿共同加载的 [分类脚本与声音表达](../../shared/script-expression.md) 落实观看推进、实际台词与结尾；此处负责把它们变为镜头及可执行动作。若注入了类型 playbook，景别、运动、切节奏和产品出镜按那一份安排。产品片和口播可以用约 2 秒的英雄定格。剧情不写英雄定格，片尾是余韵：家用物品留在原处，镜头可以推近。竖屏中轴优先。

先写 `video_flow`，再用它派生镜头。用几句说清开场用什么具体画面留人，中间怎样把已选方向的 hook 和 big_idea 看出来，结尾停在哪一个产品状态。不要按秒数把片子切成相等的段。

每镜 `description` 写能拍到的事：主体和动作、景别与运镜、光线、产品是否在画面里以及大概位置、环境、台词落在这一镜的哪一段。`camera_move` 同时写出景别和运动，例如“微距，镜头缓慢推进”。`product_visible` 为 true 表示产品在画面里，拿在手里或放在身前也算。不写如同、仿佛、好像、像丝绸一样、高级感、氛围感、象征；这些词视频模型会按字面去画。方向里的隐喻留在方向，进镜头时改成光线、材质、位置和动作。已选方向是穿梭，或这条按生活问题接到产品世界再回到结果时，每镜 `description` 用「生活世界：」「产品世界：」或「衔接：」开头，双世界才不会在分镜里收成一段。只有外观拆解、没有产品世界那一段时不要硬标。防变形只提醒保持商品外形。可选 `visual_motif` 写一个贯穿元素。相邻镜头可用 `match_cut` 标 `motion`、`color` 或 `scale`。不把九宫格当视频首帧，不加结尾 Logo 或口号，不把剧情锁成七成以上产品，不写 Seedance 或 Nano 的提示语法。最后一镜仍然大约留 2 秒产品停住。

产品出镜按本类型 playbook：产品展示大约八成，剧情大约一半，人物讲解大约七成，并且讲解时产品在手边或身前。人物讲解的第一镜 0–1 秒商品就要在画面里。剧情和产品片的开场可以是处境或气氛，商品或用法在前大约 3 秒内出现。没有 playbook 时大约七成。最后一镜大约 2 秒机位停住，产品留在画面里，不另加字卡、Logo 或字幕。切在动作完成或一个特点被看清的时候。长于约 4 秒的镜头仍是一个镜头，视频提示词会在同一次请求里写成多段运动。

手和商品：优先简单、看得清的动作，拿着讲、短暂演示、慢慢转一下给镜头看。复杂的手指操作（换风嘴、按小按钮、两手交接、快速放下或收起）只在它就是卖点时用，并单独给一个镜头、放慢。最后约 2 秒不放下、不递出、不收起。这是建议，不因此否掉方案。

1. 沿整片观看过程联合安排画面、完整台词和必要时间，再分镜。用实际内容使开场的期待、中间的展开与结尾落点相连，节奏可舒缓或有对比，不机械套三幕。保留核心、事实、固定要求、片长和制作决定；压缩重复表达，协调未固定台词与动作，并同步修订 `timing`，不照抄草稿秒数硬塞画面。
2. 每处画面落实时一起核对覆盖段落的实际 `narration`：声音是补信息、推进关系、提示或强调，还是仅复述眼前动作？保留有作用的同述，精简无作用的复述；该安静时留空，不能只写“旁白补充卖点”。改后连读全部台词，保留原意、说话对象与自然衔接，不在每镜重新介绍商品，也不凭改稿补未知效果。
3. 每镜 `description` 写观众看见的主体、所在位置与尺度、构图重点、动作顺序和光影变化；不用“高级特写”“展现质感”替代可见内容。`camera_move` 交代摄影机如何观察，`allowed_changes` 写主体允许发生什么，主体不动就明确保持，不把机位绕行同时写成商品旋转。若采用分屏、叠化或角度并置，写清画面如何出现、位置关系与运动；确实切镜就拆成相邻镜头，不能把“切至侧面再并置”整体标为未说明实现的连续长镜。全片沿同一视觉约定；有目的的光影或景别变化不等于另换场所、角色或产品。
4. 按观察重点与完整动作决定镜头数及覆盖关系，一镜可承接相邻多段，一段也可跨镜。相邻镜头可展开、对照、呼应或留出辨认时间；反复扫同一部位再回全貌却无观看收益时合并。`continuous` 只说明接续，不自动证明节奏成立；需要切换时写清真实切点和承接关系，不为“流畅”把全片都写成同速环绕。结尾让已建立的产品认识或动作落地，不用重复展示凑满余下时间。
5. 沿内容与镜头依次追踪商品、角色、道具和部件。明确持物人、位置、数量/剩余、父子物体的依附与分离：附属物随主体移动，取出、转交、移除或消耗后相应状态必须持续。每镜起态、描述、允许变化与终态相容；已经完成的动作不能重复发生并留下同样余量。头发须交代在谁的头上，或明确为独立发束/假发/概念材质；只露后脑、发丝或手仍是该人物局部出镜，不能因没有露脸把character_ids清空。未知规格和总量仍未知，不为连续性编造数值。
6. 开场直接写已存在的起态与镜内变化，无须补拍商品入场、摆放等前史，也不把这些未发生在片内的过程写作省略任务。后续落实内容稿的时间省略。`ellipsis` 须由真实镜间切点与可理解的前后状态表达，并明确省略的是切点之前还是之后的过程。入镜 `cut` 或 `scene_change` 只能省略该镜开始前的动作；该镜内新发生的取用、入口或操作，仍须按实际顺序拍到所写终态。若要省略这些动作的后续过程，本镜须结束在实际拍到的状态，下一镜用真实切点衔接省略后的状态。下一镜为 `continuous` 时不能跳过尚未完成的过程，连续长镜不能让物体突然消失、复原或提前记录完成。不得用“结束态按完成记录”、目的说明或省略声明，把未拍的吞咽、操作完成等写成已经发生。切换景别要保持空间与动作关系，“丝滑转场”不能代替接续说明。
7. 为完整语句提供语义相容的画面，先判断是否存在真实的先后依赖。旁白、同人画外讲解通常可以伴随相关商品展示与摄影机运动；需要突出某个揭示时点时再安排留白，不把“画面清楚”和“声音清楚”一律拆成先看完再说。话语只有在对象出现或动作完成后才成立，或同一人的动作妨碍发声时，才按该实际关系串行；`speech_overlap=false` 会让程序先完成本拍全部视觉动作，再说整句。`action_plan`、镜内描述和所覆盖内容须使用同一先后关系，不能在后半镜另写一个编排中不存在的“完成后才开始整句”。可合理拆分内容，但无需因此新增镜头。人物对白按既定 `speech_delivery` 安排：未填写或 `visible_only` 时整句窗口须看清本人开口；`on_and_off_screen` 可在建立可见说话者后让同一人的声音跨到商品特写，画外镜头不写入虚假的出镜角色ID。逐镜描述嘴部是否可见及何时切离，不能把手部特写宣称为可对口型；同一镜内从脸移到商品且说话可见时段不清，应调整镜头/声音安排。画外音不要求人物张嘴，不改变已选唯一说话人。剧情里没有醒着的人听时，不要写她开口说，改成她没有开口，并写上放轻脚步、回头看一眼这些表演；台词若留下，是她自己的内心独白，不谈产品。有醒着的人听，才按对口型安排。
8. 独立估计顺序动作、并行动作、必要辨认与停留，修正内容稿的视觉估计和重叠方式。用保留故事核心与固定内容所需的最少动作组织实际画面；内部草稿自拟的先后动作和重复操作可以删减。容量不足时优先在已有省略切点将未固定的重复过程整段省去，不强制新增镜头，也不把过程开始留在镜内、再无切点地宣称过程已完成。合并镜头不会创造额外时间；须同步修改实际镜头描述和状态，不能只改 `action_plan`、无依据地下调估计、假定快放或悄悄加长片长。固定内容仍无法容纳时保留具体冲突。

## 输出与交接

按本轮 Schema 返回协调后的完整 `ad_script`、统一 `visual_direction` 和全片有序 `shots`。镜头用 `coverage` 引用所覆盖的相邻内容段落及相对权重；同一内容分给相邻镜头时，权重表达各镜所需的相对份额，不是绝对秒数。覆盖顺序应与内容推进一致，不跳过段落、不把同一内容分散到不相邻位置，也不为等份分配制造切镜。

不输出临时镜头起止秒点、生成分段或 `speech_spans`。程序在本次回复后，按协调后的内容 `timing` 和覆盖权重计算内容时轴、镜头时长、说话窗口及生成段；最终实际结果交 `plan_review` 独立综合审核。内容边界、切镜边界与请求边界各有职责，不能按每镜一请求或固定秒数编排。

`plan_refinement` 只输出本次 Schema 中可编辑的 `ad_script` 和 `shots`。标题、统一视觉约定及未允许更新的三项内容摘要由程序保留，不重复输出；全局容量重组时可同步更新摘要，商品事实、故事核心、角色/声音与用户固定内容仍须保留。输入中的 `draft_storyboard` 是当前实际稿，`final_execution` 是已计算的镜头与语音时轴，按反馈及范围修正，不拿历史初稿覆盖当前稿。程序组合完整候选后继续全部校验与独立审核，固定字段的保留不能掩盖实际镜头中改变场景、角色或商品的内容。

初次分镜的 `entry_transition=continuous` 不要重复填写 `start_state`，由程序沿用前镜完整 `end_state`；返修按本次 Schema 保留或继承，显式填写仍须一致；`opening`、`cut`、`scene_change` 须完整给出起始状态。只产生文字分镜和已有素材引用，商品图、场景图是身份/环境参考；角色参考由素材阶段准备，不增加逐镜关键帧或确认步骤。

## 局部修正与失败处理

- `plan_refinement` 接收实际失败方案、全部已知定位反馈和程序给出的 `repair_attempt`/`repair_attempt_limit`，同一轮合并处理容量、状态与声画问题，使用同一输出契约，在 `repair_scope` 内修正失败相关的段落、台词、镜头及必要相邻状态。未受影响镜头保留 ID、顺序与内容；受影响镜头可合并、增删或调整，内容段落身份按范围契约保留。允许改变未被用户固定的草稿表达与时长估计，不能只修改 `purpose`、`visual_evidence` 或审核说明来宣称解决问题。
- 只有全片容量冲突且 `repair_scope.allow_beat_restructure=true` 时，可合并或删去未固定的次要内容段落，并同步重组实际镜头及 `coverage`；范围须覆盖全部原有段落与镜头。程序排时超限或综合审核发现动作窗口不足都会触发这种范围，因为固定总时长内需要重新平衡内容。保留故事核心、用户固定动作与原句，省略过程写成真实切点与可理解的状态变化。其余局部返修仍保留段落身份与顺序，不能借重命名或合并段落下调相同动作的估时。
- 局部调整影响说话先后、物体依附或消耗状态时，沿相邻内容检查实际传播范围。超出局部范围且无法保留核心或固定要求时明确冲突，不趁返修改写整片。
- 已有合法商品依据遗漏对应节拍镜头引用时，可使用剩余修正预算中的一次局部修正。按实际内容判断应移除无关节拍引用，还是让实际使用该依据的镜头正确引用；程序不会自动补 ID，也不能把补齐 ID 当作内容成立。外来事实、外来角色和其他结构错误不走此修正。
- 程序反馈 `unsupported_timing_reduction` 时，指出的段落实际动作未精简而估时降低，当前候选尚未通过。若本轮允许修正，可保留候选中已完成的实际改进，联合修正这些段落及反馈中的容量冲突；原始基准和既有范围仍有效，不能把被拒绝的新数字当成基准。`visual_seconds`只算视觉动作与辨认，整句说话另算；必须精简实际内容或明确省略，不能再次只改数字。此修正计入程序给定预算，成功编译后仍须独立完整审核。
- 修正后由程序重算时轴，再独立审核实际完整方案。本阶段不自审放行，不回旧分拆审核，也不增加用户确认。是否继续及剩余次数由本轮 `repair_attempt`、`repair_attempt_limit` 与程序决定。若收到仅自然口语问题的专用收尾 Schema，只返回其要求的 `narrations`，遵守已有语音窗口字数上限，不改镜头、动作或估时；可删未固定的旧修饰词，须保留重要句意、事实与声画关系。完整复审与停止由程序安排，不自行追加调用；已解决问题和未受影响内容保持，不能只修改说明冒充改善。
- 图片已生成后的回检须指出图片与确认场景的具体差异；不能迁就错误图片改需求或自动重做全部素材。模型不能保证原生声音、口型或最终动作表现，实际成片仍需相应质检。
