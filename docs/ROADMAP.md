## 执行和验收约定

- 每轮先说清只解决哪个问题、怎样验证、预计等待和真实调用上限；发现新问题先登记，不顺手扩展一整套改造。
- 优先复用既有证据和离线回放；需要真实调用才做针对性验证，最后才验证完整链路，失败与主动中断照实保留。
- 状态分别记录为已实施、工程验证、真实样本结果、用户验收；任何一个都不能代替另一个。
- 当前文字速度没有已验证的秒数承诺。澄清至方向可见、选方向至完整可接受方案分开计时；首个可见内容只是补充体验指标。
- 每次结束只更新这份总表的状态、证据与下一项；阶段编号保持1–6。新增范围先说明归属和代价，再实施。

## 流程、保护与范围边界

- 用户操作仍为：说明需求 → 选择方向 → 确认方案 → 确认图片 → 生成视频。广告倾向融入澄清，不增加专业问卷或一串确认。
- 九宫格、逐镜分镜图、将分镜图作为视频输入均未列为当前确定实施项。九宫格只是第5阶段可比较的候选；是否采用及如何影响流程，需看实际效果后明确。
- 联合起稿与轻量内容初稿实验未达标，当前关闭；同次两版旁白也未接入。不能将做过实验标成已完成优化。
- 主Agent动态路由、多人对白/混音、TTS迁移、批量投放、账号/钱包/多租户、全面自动剪辑和架构重写不在当前六阶段首轮交付。
- 每个阶段交付后先验收，再进入下一阶段；本轮补修也逐项交付。旁白本轮已补修并实测但尚未通过，分镜创作下一项未开始。
- 旧方案和成片保留，测试使用隔离副本；明确失败与受理状态未知分开，后者不能自动重复付费提交。生成后质量修复与供应商故障重试分开。

## 最新自动验证结论

本轮真实文字请求共7次：原模型SOL整链3次、同简报Astra纯文案对照1次、Astra分镜3次（两次读取超时，第三次主动中断）。没有新增媒体请求或生产方案写入。两条路径均未取得最终独立审核，不具备完整方案验收条件；不要求用户刷新、重开对话或重生成视频。线上仍为土豆gpt-6-sol，SPEECH_DRAFT_ENABLED默认关闭，服务未重启。

- SOL：自动写稿27.785秒，仍为“银灰与紫红，亮相高阶审美。戴森吹风机采用等离子技术，满足你对秀发护理与日常造型的关注。”；分镜250.512秒，最低容量22.7秒超过目标20秒；返修131.010秒。共409.374秒后，测试在第二次返修HTTP之前有界停止，尚未请求综合审核。
- 第一次返修实际已把最低容量降至16.3秒，第二次返修原因是未改变的开场估时3.0→2.5秒被守卫拒绝，并非仍超时长。独立纯内存回放仅恢复原3.0秒后，最低16.8秒，范围校验及编译通过。这是可减少一次返修的具体线索，尚未实施，更不等于独立审核或文案质量通过。
- 同份自动简报仅换Astra的单次写稿9.339秒，得到“戴森吹风机，以等离子技术呵护秀发。让每一次日常造型，都有精致的开场。”。独立复读认为基础可用、仍普通；单例不能证明普遍优于SOL。
- Astra接续真实稿时，逐字核对system及模型可见输入后复用上述一次真实写稿，没有重复计作新请求。导演两次分别301.476、301.261秒ReadTimeout；第三次已发出，26.685秒后主动中断。未收到任何导演正文，无完整方案可审核；不声称供应商已撤销或不计费。
- 该整链不是同档测速：现有传输覆盖只匹配SOL，SOL导演medium/600秒读超时；Astra实际high/300秒，虽然测试配置填写了medium。因此不能把完整耗时差归因于模型本身。两次文案对照均为low。

实证瓶颈已在导演与返修：SOL导演14,619输入token、4,743输出（含880 reasoning）；返修18,098输入、3,058输出（含516 reasoning）。不能把全部等待叫作推理耗时，供应商排队和网络占比未确定。下一步应先处理保守估时恢复与重复请求边界，再做限定的完整验证；不继续仅换文案措辞或推理档位，也不启动第五、六阶段。
