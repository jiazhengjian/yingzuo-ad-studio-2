# 广告脚本表达验收

这一组验收针对“商品特点与关注理由是否写清楚、台词是否退化为画面解说或稀疏泛用口号”的问题。当前运行时规则为 `ad_expression 1.1.0`。本工具检查独立广告脚本及一次有界内容审稿，不生成图片、视频或音频，不写用户项目。没有广告转化评分，也不把模型自审、字数检查或单元测试通过当作内容质量证明。

生产完整方案在方向选择后已使用 `ad_script → storyboard → plan_review` 三阶段；入口的策略判断与方向审核另行执行。本工具保留历史脚本与内容审稿两阶段的独立评估范围，不会自动执行当前生产完整链路。完整流程需要另做集成与真实样稿对照。实际回归和真实对照结果见 [VALIDATION.md](VALIDATION.md)；下文历史样本与旧审核步骤按其当时版本阅读，不能当作当前流程或质量成绩。

## 测试资料与边界

`tests/fixtures/ad_expression_cases.json` 包含四组 20 秒作者编写的输入：

| 用例 | 可用资料 | 重点 |
| --- | --- | --- |
| `cake_photo_only` | 模拟照片可见外观、办公室下午茶情境，配料口味未知 | 在不编造口感的前提下，表达蛋糕与下午茶选择的关系 |
| `cake_confirmed_facts` | 模拟商家确认黑巧配料和一人份规格 | 把有依据的商品信息转成受众关注理由，不机械报参数 |
| `hairdryer_photo_only` | 模拟照片可见外观，性能未知 | 可以从设计偏好切入，不能补造快干、护发、材质或按钮功能 |
| `hairdryer_confirmed_facts` | 模拟商家确认按键调速和挂环收纳 | 允许必要的操作说明，连贯表达使用到收纳，不能虚构效果对比 |

这些用例从创意已选定的阶段开始，商品图观察被作者预先写成文字。它们不验证图片识别、对话澄清、创意选择、分镜执行或真实生成质量。商家确认项均为合成测试资料，不能用于实际用户商品或保存到其项目。

基线区分两种来源：

- **历史真实台词**：此前蛋糕方案、一次真实文本审稿试跑中的短句，以及用户本轮指出缺少卖点的吹风机稿。保留的是无个人信息的文字，不包含项目标识、原始媒体、供应商回执或密钥。
- **构造反例**：作者编写的未完成句、动作解说和无依据性能说法。它们用于回归问题，不是旧模型运行结果。

新增吹风机实际反例为“出门前那几分钟，台面上总有个顺手的位置。每天都要拿，收进柜子反而麻烦。”它只说明常用与摆放习惯，没有把已知商品特点变成关注理由。`expected_semantic_failures` 标记应由人工或模型审稿核对的商品、受众关联问题，不是词法程序已经检测到失败。此真实文本只保存在评估夹具，运行时正反例继续使用自写的花瓶、折叠购物袋等跨品类示例，不注入固定吹风机稿作为生成模板。

历史蛋糕样本与这些合成资料不完全一致，商家确认卖点的两组输入尤其不同。对照用于解释具体表达问题，不能宣称这是控制变量后的模型提升率。

## 默认离线运行

在项目根目录运行，需要 Python 3.10+。默认仅用标准库，不导入应用、不读取环境文件、不读取任何密钥、不发请求：

```sh
python3 scripts/evaluate_ad_expression.py --output .local/evaluations/ad-expression-offline-01
```

输出必须是新目录。项目内只允许写 `.local/`；也可显式指定项目外的临时目录。已有文件不覆盖。默认检查用例 ID、事实引用、商家原句匹配以及明确反例能否触发有限的字数或断句诊断，随后生成待验收记录。结果 `not_generated` 是预期行为，表示没有生成新候选，不代表质量合格。

字数含标点和空白，整条台词暂保留每秒2.9字符的保守工程硬上限，20秒最多58字符；逐句仍需依序装入各10秒段的29字符预算，不能跨生成段接半句。已取消每秒1.8字符的固定目标，不固定20秒的句数或节拍数，按实际信息任务安排。该上限待真实音频验证，不是语速标准或音长保证。关键词诊断只标记本用例特别缺乏依据的说法；未命中不能证明事实正确，命中也需要结合上下文判断。例如否定句中出现某个词不能直接视为承诺。

## 显式运行真实文本模型

只有 `--real-planner` 才发送请求。此工具保留为历史 DeepSeek 对照实验，**不跟随当前生产策划模型**；当前产品已切换土豆 API 的 gpt-6-sol，不能用本工具结果代表该模型。需要项目 Python 依赖，以及明确配置的 `DEEPSEEK_API_KEY` 环境变量；可用 `--credentials-file` 指定本机私有文件。脚本不会自动发现或载入 `.env`，也不会读取土豆密钥。

```sh
.venv/bin/python scripts/evaluate_ad_expression.py \
  --real-planner \
  --credentials-file .env \
  --output .local/evaluations/ad-expression-live-01
```

只检查指定用例时，可以重复 `--case`：

```sh
.venv/bin/python scripts/evaluate_ad_expression.py \
  --real-planner \
  --credentials-file .env \
  --case cake_photo_only \
  --case hairdryer_confirmed_facts \
  --output .local/evaluations/ad-expression-live-02
```

每个用例最多两次付费文本请求：独立脚本 → 审稿。四组最多八次，不自动重试。复用应用的 `AD_SCRIPT_SYSTEM`、`SCRIPT_REVIEW_SYSTEM`、`script_context`、`script_request_options`、模型结构和 `validate_script`；传输层固定调用 DeepSeek 文本接口，禁用工具调用，不执行 `Gateway.decide` 的完整创意和分镜链。模型来自显式 `--model`、指定凭据文件或环境中的 `DEEPSEEK_MODEL`，默认与项目一致。

脚本和审稿请求与生产使用相同设置：启用 `thinking`，`reasoning_effort=high`，`max_tokens=12000`。更大的推理预算可能增加等待时间和用量，但请求数量仍固定为每例最多两次，不因等待自动重试。这里只读取响应中的最终 JSON 内容，不保存或展示 `reasoning_content`。

输出包含初稿、审稿结果、候选、有限诊断和人工待验收表，并记录实际运行规则的版本、内容 SHA-256 及请求设置，避免把不同规则和推理预算的运行混作同一条件。异常仅输出结构化错误；HTTP 回应正文和认证头不写文件，疑似凭据及本机路径在写出时脱敏。`.local/` 结果仍应保持私有，不直接加入 Git。

如果审稿返回 `ready=false`，或任一步结构/引用/句子完整性/预算校验失败，该用例记录失败并停止继续调用。失败稿不会自动重试，也不会传入图片或视频流程。

## 重检已有候选

可在无凭据、无网络模式下检查现有 `case_id.json`，格式支持单独的 `AdScript`、`ScriptReview` 或本脚本之前输出的记录。需要项目 Python 依赖，因为此时会使用纯合同校验模块；仍不会导入应用配置或读取生产数据。

```sh
.venv/bin/python scripts/evaluate_ad_expression.py \
  --candidate-dir .local/evaluations/ad-expression-live-01 \
  --output .local/evaluations/ad-expression-recheck-01
```

## 人工验收方法

先读完整商家输入及事实边界，再逐项阅读初稿、审稿后候选和基线。分别填写六项 `通过 / 不通过 / 无法判断`，每项引用具体句子或节拍；不填写泛泛的“更自然”。

1. **商品关联**：实际台词和画面职责是否把某项已知商品特点连接到关注理由？商品出现、事实ID正确或purpose自称有卖点均不够，不要求每句话念商品名。
2. **受众理由**：是否解释这个受众在当前情境为什么关注该特点？“每天用、放手边、收柜麻烦”等泛用习惯不能直接当成商品看点。只有外观资料时，具体可见看点与审美偏好的连接可以成立，不强行创造独家卖点或性能。
3. **事实依据**：主张是否受本用例资料支持？核对直接声称、暗示、比较及亲身体验。事实 ID 正确不等于自然语言事实已被证明。
4. **音画分工**：商品表达和演示是否共同成立？必要操作说明合理，连续事实清点和只剩稀疏泛用口号都需重写；不能为追求静音删掉必要商品信息。
5. **自然口语**：朗读是否完整、顺畅、有呼吸？检验碎句、模板口号、堆砌和过度解释；少字不等于自然。一句可以跨同节拍连续镜头，不应为了切镜截断；字数预算通过仍需后续真实语音测量。
6. **叙事承接**：开场所引出的信息或情绪是否被后文承接，商品与场景是否连贯，是否自然收束？不要求每条广告固定痛点或结尾购买引导。

有任一关键项不通过，应定位具体缺口，修改对应规则或输入后，用新目录重新运行。保留失败样本，不只展示最好的结果。模型自审结论可以辅助定位，但人工验收表默认保持 `not_reviewed`，脚本不会替人填“通过”。

## 最终音画计划的后续验收

生产分镜将整句写入 `speech_spans`，短语 `anchors` 保存连续原文、局部时间和对应镜头。人工复核应先读最终 `shot.description` 和实际旁白，再对照短语窗口；不能把编排器填写的 `visual_evidence` 或镜头purpose当作证明。台词说“用完挂起”时只有风嘴特写，仍属于计划错配；商家确认的“三档风速”可以通过声音说明，按键动作本身不能证明三档。

历史第五阶段 `alignment_review` 曾按这些最终内容检查整条广告及全部 `(segment_id, span_id)`。当前生产主链由 `plan_review` 综合检查协调后的内容稿、镜头和台词窗口，保存与方案绑定的审核记录；这仍是文本计划审核，没有实际生成音频或成片可供检查。新方案对话改稿会同时更新画面和时间并重新审核；历史无 `speech_spans` 方案保留原合同。

新视频提示由实际镜头描述与旁白时段编译，`segment.prompt` 仅作场景图的统一视觉上下文。检查应以最终实际镜头和声音字段为准，不能依赖另一份自由文本来弥补缺失画面。

文本与计划验收通过之后，仍需单独验证场景图片、真实台词、音画对应、声音自然度和视频衔接。实际广告表现要依靠后续投放反馈，此文本验收不作相应承诺。
