## 2026-10-08：剧情和口播少被窗口和落点误伤

镜头实际够长时，不再因为相交动作窗口比镜头更短，把模型已经给的通过改成未通过。动作比这一镜本身还长，仍然改成未通过。这条没有加进八条硬门。

口播里写成没说话的镜头，不再被同一句台词盖住。只有手的特写不再承担需要露脸开口的台词。同一人画外接着说、而且这句里已经有露脸镜头时，手部特写仍可以接着。剧情里没有醒着的人听时，手里的特写可以留下内心独白。同一场如果跨了生成段，醒着的听众按全片算，只在换场处分开，和内心独白同一套。上一段还坐着朋友时，下一段没换场的手部特写不再留下要开口的台词，画外也不会当成内心独白。这一段写明她一个人时，不去借上一段的人。挪不动就留下，不因此停住。

把开口说改成心里想，发生在审核之前。放行前再按同一规则走一遍，硬门看到的是改过的字。合同对不上的改写会放回去，不留一份审核没见过的稿。没有醒着的人听时，审核把这句标成画外，不再把通过改掉。有人醒着听，或者看不清，仍然不能通过。

## 2026-10-07：澄清先问类型、卖点和人群

每轮澄清 1 至 4 题，已经知道的信息就少问。广告类型还没选时，第一张卡可以同时放广告类型、最想记住的一点、拍给谁看、去向。同一张卡上选了剧情，去向当场收起，也不记成要念出的目的地。已经确定是剧情时不再问去向。

## 2026-10-06：状态参考只认分镜声明的变化列表

分镜要自己写出 `state_changes`。每一条包含主体称呼、归属（角色 id 或 `product`）、起始外观、结果外观、起始镜和结果镜。只写文字锁不住的可见外观，例如头发湿到干、乱到顺、容器从满到空。开关机、拿起放下，以及视频自己能演的动作不写。15 秒及以内每个角色最多一条。程序只核对镜头存在、起始镜在结果镜之前、归属是已知角色或商品。对不上的条目放下，并记一条软警告，不从镜头正文再猜。

标签和提示用声明的主体和起止原文，例如「头发湿·起始」「头发干顺·结果」。角色锁定外观会去掉这条声明里的状态词，身份句里不再留下「半湿」；湿或干只出现在起始和结果那两句。结果图按同一条的编号去改那张起始图，起始图的素材编号写进结果图的参考输入，提示词面板能看到。

## 2026-10-04：非流式长请求被代理切断后改走备用策划

`PLANNER_STREAM=off` 时，土豆 `gpt-6-sol` 的方向生成会在大约 100 秒被上游掐断。这个断开不是本地读超时，也不是 HTTP 504。`_planner_json` 因此不切换备用模型，只抛出可重试的 `PlannerRequestError`。`PlanningSession.call` 把这种失败再试两次，每次仍从主模型重新开始；`on_retry` 写成「策划服务暂时中断」，紧接着 `on_start` 又把阶段拨回「正在判断是否需要补充信息」。单次等待上限是 270 秒，管不到这几次重试加在一起的时间，所以一步方向可以超过 7 分钟。连接断开也不会写诊断文件。

初稿若仅有可定位的单句长度问题，将原文交给既有分镜协调步骤改写，不在程序中截断；最终方案仍严格检查单句长度和全部内容。动作未变却降估时的首次修正失败可使用剩余的一轮预算，仍以合法原稿作基准，第二候选不带旧稿时间轴。初稿现使用低强度思考，撤回未经质量验收的直接输出提速配置；分镜、返修、综合审核采用高强度思考。说话人可见性由新鲜综合审核逐句给出并按已确认声音形式保守汇总，历史审核保持兼容。配置及字段的增加不等于真实质量已达标。

## 本轮接续与已有成果保护

策划请求现保存私有阶段检查点，临时连接失败自动有限重试，进程重启复用已完成输出；最多两轮常规内容修正，每轮完整复核；两轮后仅剩台词自然度不通过时，另允许一次只改台词的收尾，再次完整复审。无改善提前停止。已有成片与本次修改分开显示，历史失败项目仍可直接播放下载原视频。通用“恢复任务”已从主流程移除；只有请求暂时失败且自动重试耗尽时才提供明确重新尝试，内容和配置问题给出相应处理入口。开发验收采用隔离项目和模拟供应商，未向已有成片对话追加验证消息；真实出稿成功率和成片质量仍须另外验证。

## 已实现的制作流程

1. 选择 10–60 秒时长，上传最多 3 张商品图片。后端检查文件、处理方向、移除 EXIF，并限制图片尺寸。
2. 策划模型根据需求、图片、已回答问题及当前方案，选择回复、澄清或制定方案。需要补充时每轮提出 1–3 题；题数不按有图、无图机械确定。澄清逐题进行，自由回答使用底部输入框，最后汇总提交；未提交草稿可在当前标签页恢复。
3. 资料足够时，整理可追溯商品事实、未知项与创意假设，生成恰好三个方向。独立 `direction_review` 核对动作与状态合理性、商品作用、吸引方式及三方向差异，可在这一次审核中修订，全部通过后才展示；未通过不把草稿交给用户选择。最多一个标推荐，不预选。卡片展示带“方向：”前缀的创意标题、故事概要和怎样吸引观众，另用一行说明出镜人数、声音形式和预计生成图片数量，不展示创意依据或制作说明。用户点击后由脚本规划（含台词方法）完成内容稿，再协调内容与分镜，由程序排定最终时间，最后独立综合审核内容和声画。方向选择保存候选版本及上下文；旧卡不能操作新候选，重复点击不产生重复续写任务。普通局部修改沿用已选方向，明确换创意才重开候选。修改意见沿用统一输入框，无重复弹窗、表单或右侧营销报告；旧方向没有保存的人物与声音决定不在界面补造。
4. 新方案分别保存镜头与 `speech_spans`。完整台词可跨支撑同一内容任务的相邻镜头，用短语 `anchors` 对应内容与时间；同一长镜头也可通过 `beat_ids` 承接多个相邻内容任务和完整句，不按节拍数量或固定秒数强制切镜。不能跨明确场景转换硬并长镜头，也不能跨独立生成请求接半句。人物对白须绑定已确认说话人和对应出镜窗口。“修改台词”沿用对话输入，重排台词、画面和时间后重新审核。旧方案仍可读取并按原方式编辑，直接编辑旧镜头台词会清除旧内容脚本与审稿绑定。方案位于策划回复后，分镜默认收起，展开后查看实际镜头和对应台词；图片确认与视频生成期间保留展示并禁用修改操作。
5. 方向与方案的 `production` 保存有事实出处的商品形态/数量关系及动作约束、全部出镜角色的创作设定，以及画外音、指定角色对白或无人声三种声音形式。人物对白本版只有一个指定说话角色，其余角色不说台词；它不等于独立主播口播入口。后续分镜不得擅自改写已选决定。点击方案“确认”直接准备图片：复用上传商品原图，生成一张场景图，并为每位角色生成一张 16:9 横版身份参考（左侧脸部与上胸特写，右侧正面、侧面、背面全身）。新角色图记下模板版本 `chinese-horizontal-v1`。继续制作时，未确认且尚未提交视频的旧角色图会按这个模板重出，场景图仍复用；图片已经确认，或视频已经提交，就不再换掉已保存的角色图。新增图片数为 `1 + 角色数`。没有逐镜关键帧或首尾帧。场景和角色请求使用各自模板，新请求及编译版本随回执保存；恢复旧图片保留原请求与版本。
6. 每张图片完成后立即登记并展示，后续图片失败仍保留已完成素材。场景及全部计划角色图准备齐全后，沿同一个图片确认节点检查商品、场景与角色，不为四个视角增加独立卡片或确认弹窗。新 `production` 方案不能跳过图片确认直接提交视频；发送修改意见则先回策划。明确失败的图片不在原任务自动重画，界面提供修改方案入口；受理未知时停止重复提交。
7. 新视频请求由服务端从实际镜头描述、台词时段、短语对应及已确认商品/人物/声音约定编译。参考图按实际使用顺序绑定：全部计划引用的商品原图、场景、按角色顺序排列的四视图；支持多张商品原图，不把第二张商品图错当场景，超出模型图片容量时拦截。逐镜人物与台词共享这些身份绑定。`segment.prompt` 不另行覆盖定稿台词；旧方案缺少场景字段时可保留其视觉上下文作为兼容输入。按完整生成段提交视频，合成为选定时长的竖屏 MP4；可查看片段、当前版和历史版，下载实际媒体文件。

工作台通过真实执行事件展示进度，等待用户时停止计时并释放执行器。SQLite 保存会话、项目修订、任务、确认节点和产物；重启后按已有回执恢复。新任务或版本变化不会让旧结果覆盖当前方案。

图片与视频使用的 Skill 在原有折叠执行记录中显示名称、实际版本与“按 Skill 编译”。来源只取已持久化的场景/角色图设计记录、图片请求回执的真实编译 trace，以及视频提交前冻结请求中的 trace；同任务同版本去重，不读取当前注册表冒充历史版本。新图片请求在实际编译记录保存后即登记来源，因此运行中或失败后也可显示，已有成功任务可从原素材记录恢复展示。此展示不增加模型调用，不新增历史事件或改写执行时间，不公开提示词、素材路径、供应商 URL 或凭证；没有保存来源证据的旧任务不补造 Skill 使用记录。

视频提交前重新核对远端商品原图的完整字节、已确认场景与角色图的实际像素。图片链接过期时，只将已保存且经哈希核对的相同本地图片重新上传并验证，不重新生图或用新内容替换。明确失败的视频可点击“重试失败片段”：在相同方案版本建立独立任务，复用确认图片与成功/已受理片段，仅分配已失败段的新增提交额度。重试保留原冻结提示词及输入契约，并核对原资产 ID、顺序与哈希，新增字段或 Skill 更新不能改变旧请求。原任务和回执保留，重复点击返回同一子任务；未知受理状态不允许重复提交。不同片段已受理后，一段终局失败不再阻断其余片段取回。

## 第一阶段策略的实际范围

本地规则包含感官细节、生活情境、外观揭示、操作讲解、问题与解决、有依据的对比。第一阶段收到全部 6 条规则，服务端校验方向所属品类、引用事实和使用前提；后续内容与分镜阶段只使用已选方向，不混入其他候选；内容阶段仍可引用全部已核对商品事实。规则来源与版本随计划保存，未执行外部搜索或案例检索。

商家事实要求引用本轮来源中的准确摘录；澄清答案只采纳用户选中或填写的内容，排除模型的问题正文与引用文件名前缀。句内限定检查阻止部分省略否定或不确定表达的摘录。图片事实只能引用本轮商品原图 ID；未知信息和假设不能满足事实引用或规则前提。

这些是来源与结构约束，不是商品真实性或完整语义审查。它们不能证明图片中的观察正确，不能完整理解反讽、跨句矛盾或隐含否定，也不能保证分镜实际表达与引用事实完全一致。商家仍需检查商品事实与生成内容。

正式方法位于 `app/skills/ads-video-*/SKILL.md`，显示名以 Ads Video 开头，YAML 名与文件夹使用小写连字符。注册 8 份：声音方向（已并入创意策略）、脚本规划（已并入台词）、分镜、素材提示、视频提示、计划审核这 6 份接线；参考检索和成片质检仍是 pending，不进默认流程。入口判断和商品理解写在策略主提示里，不再单独成 Skill。运行时按阶段读取正文和注册资源，记录实际加载版本/哈希，不把整套技能一次塞入所有请求。方向审核与最终方案综合审核分别调用 Plan Review。旧的内容初稿、旁白初稿、旧分镜时间线和旧分拆审核附录已删除；这些调用若仍发生，改加载现有的脚本、分镜或方案审核资源。Skill 数量不等于模型调用或用户确认次数。

[Skill 索引](SKILL_INDEX.md)提供资源和调用位置。旧 `ad_expression 1.3.0` 保留历史兼容；新脚本的 `skill_version` 仍是旧数据协议兼容版本，由服务端记录，不再要求模型抄写；正式 Skill 的运行版本以 `skill_trace` 为准。实际台词与画面须兑现具体商品关注理由，不能靠 purpose 自述、泛用生活感慨或动作复述代替广告表达。

场景、角色和视频编译器读取对应 Skill 的媒体模板；素材使用商品原图、一张场景图以及每角色一张组合四视图，没有逐镜关键帧。运行记录展示实际阶段与 Skill 元信息，不展示模型内部思考。Reference Research 与 Video Review 仍为 pending：外部参考检索、实际图片与分镜的语义回检、产品内 ASR、音色及真实音视频自动质检均未接入，不能因为规范文件已存在就声称这些工具已执行。

一次未重试的新创意完整流程，选择前执行 `strategy` 和独立 `direction_review` 两次请求，通过后等待用户选择；选择后执行 `ad_script → storyboard → plan_review` 三次，合计通常 5 次文本调用。普通文字修改先经 1 次 `strategy` 路由，再沿已选方向走这三个核心阶段，通常 4 次；不重新展示三方向。综合审核失败最多追加两次 `plan_refinement`，每次成功排时后独立全审，最多增加 4 次；两轮后若唯一问题为台词自然度，可另加一次窄台词润色与完整复审（至多 2 次请求），仍受整轮 12 次自动请求上限约束。确定性容量或生成分组冲突与内容修正共享两轮上限，一次容量修正后仍可使用一轮语义修正，不叠加旧结构时轴返修。仅改说明、问题未改善或预算耗尽提前停止；通过全部检查才保存方案，原方案和媒体保留。

问候或澄清使用 1 次策划调用。上述次数不含供应商空回复恢复：单轮对话仅对正常结束但正文为空的文本返回，允许在原步骤重试一次，共享一次额度，不重跑已完成步骤。重试前检查取消及版本，记录实际重试事件；第二次空回复停止。非空畸形 JSON、截断、HTTP 错误或内容审核不通过不触发该恢复。主动重试或新对话另计调用，图片与视频另计提交。

| 分段 | 新方案10–30秒一次生成多个镜头；31–60秒按完整表达与场景转换分组，每次2–30秒；旧方案保留原10秒回执与短尾裁切 |
| 声音 | 新方案明确选择模型画外音、指定角色对白或无人声；对白本版仅一个说话角色。旧画外音兼容 macOS TTS |
| 字幕与尾字 | 新原声路线尚未转写音轨，不叠加估计字幕；独立结尾文字功能已移除 |
| 连续性 | 新方案减少独立生成边界，连续动作不拆开；同次请求约束人物声音、商品与场景状态。跨请求仍不能可靠锁定声线；无自动找切点或接缝修复 |
| 改稿 | 新旁白方案通过对话联动重排画面与时间；旧方案保留原文字编辑；修改后重新确认，不承诺局部像素不变 |
| 策略能力 | 6 条创意规则、8 份阶段 Skill（6 项 active，参考检索与成片质检仍 pending）、经独立审核的 3 个可选方向、内容稿及台词、分镜协调和独立综合审核；没有实时案例检索、外部市场研究或投放反馈 |
| 执行与费用 | 有提交次数上限、回执、取消和恢复；无钱包、人民币封顶或自动退款保证 |
| 部署 | 本地单用户、单 worker；无账号、多租户、对象存储、分布式队列或广告自动发布 |

镜头计划的时间与台词是生成要求，不是最终视频实测时码。有声方案导出清单的 `expected_speech_timeline` 保留预期安排，`audio_alignment_status` 和声线一致性仍为 `not_verified`，需要人工完整检查声画。只有明确 `production.speech_mode=none` 的方案允许缺少供应商音轨时本地加入静音轨完成合成，不补配音、不声称试听通过；相应语音对齐和声线检查标记 `not_applicable`。其他声音形式及没有明确无人声决定的旧方案仍检查音轨存在。音轨存在不代表台词、口型或音色已审核；无人声计划也不代表已自动验证模型没有说话。模型可能调整镜头与讲话节奏，也可能改变商品外观。场景或四视图提示约束不等于图片语义验收，仍需在生成视频前检查实际场所、角色及商品。

台词不再设每秒1.8字符的固定目标。暂保留每秒2.9字符、含标点和空白的保守工程硬上限，20秒最多58字符，本版单个内容节拍仍最多29字符；生成段按实际时长检查。按信息任务决定篇幅，整句不得跨生成段。上限待真实音频验证，不是语速标准，只限制计划容量；最终模型审核也只审计划，不保证发音准确或句子严格落在指定秒数。原图字节复用也不等于生成视频保持了全部商品细节。

新生成策略只启用于当前核验过2–30秒图片参考请求的Wan模型；不把这一上限套到任意视频模型。短广告目前固定一次生成，不提供任意短段拆分或局部视频重做。历史10–30秒原声方案可经受版本、原图哈希与确认回执校验的连续性升级入口创建新版本，保留绝对镜头及台词时码，复用已确认图片，不改写旧版本。

## 平台与数据维护

macOS 已实测。新原声流程没有系统 TTS 依赖，Linux 具备运行基础，但本次尚未验证安装、FFmpeg 与完整工作流。代码使用 `fcntl` 文件锁，Windows 不直接支持；旧画外音流程依赖 macOS `say`。

服务只绑定本机地址，同一数据目录只能有一个 worker。停止服务后再备份 SQLite 与媒体文件，恢复时保持两者一致；数据内存在绝对路径，跨目录或跨机器迁移需要重定位。不要仅复制 SQLite 后假定所有历史媒体可用。

`.local/`、`data/` 和 `.env` 属于私有本地内容，不进入公开提交。正式发布前还需确定项目许可证、核对第三方依赖许可，并准备可公开素材制作的示例。


## 本轮三阶段编排与未结项

`Settings.progressive_planning_enabled=True` 为常规产品默认。`ad_script` 给出可协调内容稿，每段包含动作/辨认时长、说话能否并行、起止状态与时间省略。`storyboard` 可以调整未被用户固定的草稿台词和动作，同时返回完整协调稿及有序镜头；镜头用 `coverage` 关联相邻内容和相对时长权重，不输出临时秒点或生成段。程序此后统一计算内容窗口、镜头时间、完整台词窗口及生成分组，避免先锁台词时间再硬挤画面。连续镜头可继承前镜结束状态，显式矛盾仍拒绝。

`plan_review` 对实际最终方案一次审核六类内容表达、动作容量与状态接续、全部镜头和台词窗口。它必须核对父子物体依附、消耗状态、动作先后、说话人和实际动作窗口；不凭目的字段或作者自述判通过。审核只返回结论，不在同一次审核中改稿后自我放行。服务端保存 `plan_review` 并用内容哈希绑定所审方案；任何实际内容修改都不能沿用旧审核。已有失败的子项或数值超时只向上汇总为失败，不把失败升为通过。

每轮 `plan_refinement` 只修改失败相关内容、镜头和必要相邻状态，未受影响内容由程序保护。镜头可在允许范围内合并或增删，保留商品事实、用户固定台词、故事核心、角色/声音与片长；随后重新排时并独立全审，不重跑商品和方向，不新增用户确认。内容稿使用直接输出；分镜、局部修正和综合审核保留 low 推理及足够输出额度。每次请求记录实际阶段、耗时与数值 token，不保存隐藏思考。

旧自定义适配器未提供新开关时，继续沿用选择后的四阶段协议，旧 `ScriptReview` 和 `alignment_review` 记录仍可读取，不自动迁移或伪造综合审核。已有方向的修改上下文去除旧审核/追溯及未选候选，只影响本次发送副本；用户原始要求、澄清、商品事实及实际脚本分镜仍保留。

本轮继续工作的现有项目已到 revision 3，包含角色图、场景图与成片，不能按旧交接快照当作没有媒体。本轮优化与验证范围为文字策划，不提交新的图片或视频生成。此前 V2 的完整策划耗时和动作顺序问题属于历史基线；本轮能否改善等待体验与内容质量，仍须以完整方案的实际耗时、调用与返修数和独立复核为据，不能用初稿速度或调用数减少代替验收。
