## 每张方向卡必须回答的问题

| 用户的问题 | 字段及核对方法 | 不足以通过的内容 |
| --- | --- | --- |
| 主打什么 | `angle`。说明本方向有依据的核心表达与主次；其他本轮必需内容仍由本候选实际呈现，核对 `evidence_ids` 对应原始事实。 | 商品名称、有人使用、画面高级、参考图一致；把未知功效写成确定优势。 |
| 为什么与目标观众有关 | `audience_value`。说明该特点与具体选购关注、使用情境或审美偏好的关系。 | 所有人都喜欢、提升生活品质、适合每个人；无依据的快干、省时、不伤发等结果。 |
| 怎么体现 | `product_expression`。指出具体展示、情境变化或讲解安排，使上面的商品价值可理解。 | 只摆放商品、只出现品牌、人物满意微笑；标题写了卖点，实际展开没有表达。 |
| 这条片具体会怎样展开 | `story_summary`，界面称“创意展开”。按主要表达方式描述开场、推进、收束，不要求所有类型都构造小短剧。 | 只列镜头术语；产品展示硬加人物冲突；人物讲解只剩工作蒙太奇加全知旁白。 |
| 三个方向有什么可选的差别 | 横向读三个方向的观众关注、观看问题、产品参与方式和展开。 | 同一概念只改标题、场景、颜色或摄影角度；为了差异虚构三个新功效。 |

`attraction_mechanism` 仍解释观看期待，但它不能替代商品价值。`reason` 仍是创意选择依据，不新增同义的营销报告。字段非空、审核标记为真只证明结构完整，必须阅读实际展开判断内容是否成立。

## 本轮补充：影片结构与视觉构思

新 `brief.creative_intent` 分开用途环境、明确成片地点要求、参考意图与结构偏好。使用场景不是拍摄要求；历史 AI 设定不是用户要求。`film_concept` 保存 structure、key_visual、memory_anchor、sound_role，创意展开仍由 story_summary 承担，避免再写一份完整剧本。

- 参考已明确纯产品概念时，三条都在该范围内竞争；没有结构偏好时按商品需求构思，不强凑三种结构各一条。剧情／场景和人物讲解保留各自主要表达。
- 允许产品的形态、光影、运动本身组织内容；没有人物或台词不自动合格，有手部或一句旁白也不自动变成剧情。先看观众实际能接收什么，再判断是否传达了主打特点。
- 三个功能标题不是三个创意。风带起发丝—切局部—发丝落下重复两遍，不能靠微距和标题差别通过；不同视觉机制应有可观察的差异。
- 图片里的银色观感不能确认金属材质，可见孔不能推出散风机理、均匀出风或护发效果。审核删去功效形容词后，也不能新增这种视觉因果。
- 同次审核可纠正既有图片观察的文字，不增删事实或改商家原话、来源ID、用户意图。纠正文本和原生成响应都需保留。不能可靠修正时仍应如实未通过。

追加检查 V16：用途为理发店且用户要纯产品参考，片场要求为空，三方向实际主导结构为产品视觉。
V17：明确要求整片在办公室拍时继续保留；不得以分离用途为由抹掉真正场所约束。
V18：三个方向同结构同卖点但视觉机制不同可以成立；同过程改标题/机位不能成立。
V19：纯产品可用短旁白补准确功能信息，画面不必承担其无法证明的功效；无语言方案也需说明观众能看懂什么。
V20：选择后再改台词或时长，结构/参考/明确片场不会被清空；明确换背景只释放背景修改，不同时清空参考。
V21：新创意的产品影棚场景传给场景图与文案时，不退回 brief.scenario 中的理发店用途。
V22：既有图片观察能纠正，商家事实/来源/事实集合不可改，负面审核同样受约束；旧记录缺纠正字段不补记录。

## 本轮补修：每条候选独立回应广告要求

三个候选供用户选其中一条，不默认是合在一起才覆盖全部要求的系列。共同方法维护在 `shared/product-evidence.md`；生成、同次方向审核、选中后的脚本/分镜和最终审核承接同一要求，不新增字段、问卷或模型阶段。现有 `product_role_passed` 检查单条的完整回应；仅标题或备注提及、实际声画没有承接仍不算覆盖。

| 边界样例 | 验收要点 |
| --- | --- |
| 用户在广告目标中要求外观好看、高级，同时讲已声明的技术与护发功能 | 每条候选都回应这些内容；视觉可承担外观和风格，声音可补功能意义，允许主次，不用其他候选补缺口。只报技术名称却不传达用户要求的功能意义也需检查。 |
| 用户明确外观、护发任选一个重点，各方向可以不同 | 按授权取舍，不因某条没有另一个可选卖点而拒绝。 |
| 产品资料列出多种属性，用户没有要求全部介绍 | 选适合方向的可靠信息，不把整份资料升级成必讲清单。 |
| 要求表达功能但没有依据，或已知功能被扩大成修复/具体效果 | 不为覆盖率编造机理、量化或实验；缺真正必要事实时说明缺口，已有声明不因缺参数全部删掉。 |

本轮用户要求修正先前“至少一项”过宽标准，属于第二阶段补修。历史样本与测试夹具不批量重写；规则修订后的真实验证结果见 VALIDATION.md，未跑到的边界不预填真实模型通过。

原任务隔离复跑最终三条均在实际展开及声音任务中承接外观与等离子护发。初稿仅提技术名称的问题由同一次审核补齐，同时移除发丝变顺滑的未确认效果暗示。上述第一种边界有真实样本证据，其余三种尚未真实模型实测；三条均以收束旁白补功能、声音安排单一，不能把本轮覆盖检查等同于完整创意质量验收。原卡不回写，用户可在原对话输入“按原要求重新给我三个方向”验收新规则。

不同表达方式可以混合。判断依据是主要的信息组织方式，不是“有无人物”“有无旁白”或出镜时长的一条硬阈值。产品展示可有一句解释，剧情可有旁白，人物讲解可切商品特写；这不自动改变主要类型。

广告分类上，讲解者的声音延续到商品特写仍可以属于人物讲解。但当前 `ProductionPlan` 整片采用一种 `speech_mode`；后续审核要求 `character_dialogue` 的每个说话窗口看得见指定角色开口。因此本阶段可执行概念先采用“可见讲解与商品特写停顿穿插”，不能把商品特写中持续说话当成已支持能力。第三阶段如要支持同一人物画外延续，应显式调整契约与审核，不把 `off_screen` 谎称 `visible_speaking`。

## 人工正反样本

下列简要概念专门用于判断方法，不是运行时模板。没有写在输入中的功能不能从相邻样本借用。好样本不要求模型逐字照写，也不等于完整方向 JSON 或可直接生成的脚本。

### A. 同一卖点，三个展示概念

**测试输入**：一款虚构吹风机；测试商家明确提供“风速与温度可分别选择”；目标是为美发师介绍选购关注。没有提供具体档数、控制方式、吹干用时、噪声或护发效果。选择产品展示广告。

三条共同 `angle` 可直接写“风速与温度可分别选择”。

| 概念 | 为什么在意 | 怎样体现与展开 | 通过边界 |
| --- | --- | --- | --- |
| 两件事，分别选 | 选工具时需要了解风速选择和温度选择是否绑定。 | 把风与温度作为两个分开的选择维度建立视觉节奏，再回到完整产品。抽象图形承担概念说明，不伪造真实内部结构或检测画面。 | 两个选择维度来自给定事实；画面没有擅造按钮位置、档数或温度读数。 |
| 先提出选择，再看这台 | 先想清自己在意风速还是温度，更容易理解这项设计。 | 开场呈现选购时的两个关注，产品作为回答出现；以“可分别选择”的解释收束，不演示未经确认的操作。 | 观看机制是问题到答案；不声称已实测更省时或不伤发。 |
| 选择关系看得见 | 抽象功能说明需要让人明白两个维度的关系。 | 用明确示意的并列视觉关系解释独立选择，再与产品全貌关联，突出这种选择结构。 | 若实际画面与第一条完全相同，仍应判重复；必须读具体展开确认展示逻辑有别。 |

第三条是**边界样本**：独立选择与并列图形不天然构成另一创意。如果“两个维度逐一展示”与第一条没有可观察的差异，就应改掉该条，不通过改标题强称三条成立。正例的用途是说明相同卖点可以复用；它不豁免表达差异检查。

**反例**：三条分别改写为“风速更猛”“恒温不伤发”“干发快三倍”。它们看似差异大，却越过给定事实。另一个反例是三条都写同一操作，只把背景改为黑棚、理发店、家中。

### B. 有依据的轻场景与无依据的剧情结果

**测试输入**：一把虚构折叠伞；测试商家明确提供“按手柄按钮可以自动开伞，收伞需手动”；目标为通勤人群。选择剧情／场景广告。未说明可单手完成全部过程、抗风等级或绝对不漏水。

**合格概念**：通勤者在门口准备出发，看见外面下雨，取出伞并按按钮展开，然后进入雨中。主卖“按按钮自动开伞”，观众在意开伞步骤。情境让操作用途可理解，不制造大雨测试和性能比较。可有同期动作声，也可有简短解释；完整台词留后续阶段。

**不合格概念**：人物被客户批评，拿起伞后突然变得自信，接着获得晋升。产品虽出镜，却没使“自动开伞”对观众变得可理解。

**越界概念**：一手抱娃、另一手从包内取伞到开伞、关伞、收好全部一键完成；暴雨狂风里衣服完全不湿。已知按钮开伞不能支持整串动作能力或性能结果。

### C. 人物讲解与工作蒙太奇的区别

**测试输入**：一款虚构阅读架；测试商家明确提供“有三个支撑角度，可折叠收纳”；面向在桌前看书的人。选择人物讲解广告。未提供重量、尺寸、治疗或减轻颈椎问题的证据。它是补充案例，已被本次设计阅读，不再声称是未参与调试的盲测商品。

**合格概念**：同一讲解者向观众提出“选阅读架，我先看角度和收起来的样子”，在讲解者开口可见的画面中介绍三个支撑位置与折叠状态，停顿时插入商品细节。围绕选择依据组织内容，不靠假装长期用户经验建立权威。

**不合格概念**：人物从早到晚读书、工作、喝茶，外部旁白只说“清晨，他翻开书；夜晚，他仍在阅读”。即使演员入镜很多，也没有面向观众介绍产品，三个角度和折叠特点均未被理解。

**越界概念**：“我用了三个月，颈椎问题好了”“减轻颈椎压力 80%”。虚构角色可以说符合情境的选择理由，不能冒充真实使用者或医学／性能证明。

### D. 只有图片也能构思，但表达范围有限

**测试输入**：仅一张可见白色裱花、红色果实装饰的蛋糕图。用户允许先围绕外观设计，未说明水果品种、配方、口味、重量、人数或配送。

**合格概念**：围绕红白色彩、装饰细节和整体造型建立揭示，说明适合在意桌面视觉搭配的人；“适合”是创意设定与审美判断，不能借机承诺某项客观性能。剧情形式可以让人物为聚会选桌面焦点；无需编造成分或食用效果。

**不合格概念**：外观图直接证明“低糖不腻、动物奶油、四人刚好、当天现做”；人物吃后惊喜被作为这些说法的证据。制作要求“与原图一致”也不能作为消费者购买利益。

### E. 概念层的声音职责

**可接受安排**：产品展示用声音解释观众在意的选择关系，画面展现相应形态或使用；人物讲解回答选购问题，插入特写；剧情由人物对话推进决定，必要旁白补充背景。

**应修改安排**：声音唯一任务是逐项读“镜头推进、产品旋转、人物拿起”。操作教程中指出必要操作与注意事项可以成立，不能见到动作动词就一律判错。

本阶段只核对概念的声音身份与信息任务。逐句是否复述画面、语速与时长、说话时谁出镜、口型和原生音频质量仍需第三阶段及成片阶段验收；不能从概念字段完整推断这些问题已解决。

## 事实边界

1. `evidence_ids` 引用存在不等于正文主张被支持。逐项读 `angle / audience_value / product_expression / story_summary`，特别查隐含结果，例如“赶上下一位客人”是否暗示未经证实的更快干发。
2. 商家原话属于提供的依据，不自动等于独立核验。图片仅支持可靠可见项，不支持触感、材质成分、内部结构、温度、性能或长期体验。
3. 受众洞察允许是合理创意假设，例如“选购时在意如何调节”；不能伪装成消费者调查统计，也不能反向推出产品已实现该愿望。
4. 演绎的人物可以选择、操作、交流、微笑。不得把这些行为改写成真实用户见证或未知功效的实测证明。
5. 没有规格不等于完全不能创作。可在已知外观、用途、关系范围内构思；只有缺口确实决定当前方向能否成立时才沿用必要澄清，不要求人人填完参数问卷。
6. 同一可靠事实可以支撑三条方向；三条不必覆盖三个不同卖点。商品可替换性可作诊断线索：相近商品共用某项利益并不必然无效，但完全删除商品特点仍不影响故事与观看期待，说明价值关联不足。

## 执行与记录

工程验证在干净源码导出、临时数据与替身供应商中执行。核对新结构、历史兼容、审核遗漏、选择后交接、前端展示与调用次数；真实模型请求只有属于明确授权的任务时才运行。替身验证不能作为生成质量已通过的证据。

人工内容验证应保留首次候选与审核修订后的候选，分别判断；不只保存最好的方向。至少覆盖三种表达、单一卖点、仅图、事实不足、同类重复与混合声音安排。若运行真实模型，记录从输入齐备到三个可选方向显示的完整时间及实际请求数；方向生成、一次独立审核、结构修复分别记录，不新增循环试到成功后再报成功。

选中方向后的脚本作为交接观察对象：本阶段验证选中内容与字段没有丢失，不把脚本整体质量列为本阶段已经完成。媒体不因本次代码上线而重新生成。旧卡没有新字段属于历史记录，新逻辑需新生成一组方向才能验收。
